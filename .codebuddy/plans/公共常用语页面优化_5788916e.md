## 需求概述

优化管理后台「公共常用语」页面（`/admin/canned`，对应组件 `CannedResponseManager.vue`）的三处交互，属于既有页面的细节改进，不新增功能模块。

## 核心功能

1. **搜索改为分类作用域**

- 现状为全库全文搜索（遍历整棵分类树）；改为只在“当前鼠标选中的分类”范围内搜索。
- 搜索范围含该分类的所有下级分类；命中项上方标注所属分类路径，便于定位（选中分类自身命中的条目不显示路径）。
- 未选中任何分类时，搜索不产生结果，沿用“请选择左侧分类”提示。
- 切换到另一个分类时保留已输入的关键词，方便用同一关键词在不同分类间连续查看命中。
- 右侧列表标题在搜索状态下体现“分类 + 关键词 + 命中数量”；无结果时沿用现有“未找到匹配的常用语”文案。

2. **去掉分类行右侧的数量**

- 左侧“分类”树中，每个分类名右侧不再显示该分类下常用语的条数；其余（展开/折叠箭头、悬浮出现的操作图标）保持不变。

3. **分类行内操作图标补齐“上移 / 下移”**

- 保持现有的“鼠标悬浮才显示图标组”的交互与样式不变，不改为常显。
- 每行图标组最终为 5 个：新增子分类、上移、下移、编辑、删除。
- 上移/下移作用于同级（同一父分类下）的分类，位于该级第一个时禁用“上移”，位于最后一个时禁用“下移”。
- 操作后分类顺序立即刷新，当前选中的分类保持不变；失败时给出错误提示。
- 「分类」标题栏维持原有两个图标（展开/折叠全部、新建分类），不新增按钮。

## 边界与约束

- 不改变导入/导出/下载模板/全部删除/新建分类/行内改名等既有行为与视觉风格。
- 行内处于“改名编辑态”的分类行不显示图标组，保持现状。
- 搜索状态下，右侧条目的上移/下移仍保持禁用（既有逻辑不变）。

## 技术方案

### 技术栈

沿用现有技术栈，无需引入任何新依赖：

- Vue 3 `<script setup>` + Composition API（`ref` / `computed` / `reactive`）
- Tailwind CSS 工具类 + 项目共享 UI 组件（`@shared-ui/components/ui/card|button|input|textarea|spinner|dialog|dropdown-menu`）
- lucide-vue-next 图标（所需图标均已 import，无需新增）
- vue-i18n 文案（复用 `globals.terms.moveUp` / `moveDown` / `edit` / `delete`，中英双语已存在，预计无需新增键）
- 数据接口：`api.getCannedResponses()`、`api.updateCannedCategory(id, { name, parent_id, sort_order })`（均已存在）

### 实现策略

改动集中在前端单一组件 `frontend/apps/main/src/features/admin/canned/CannedResponseManager.vue`，**后端与数据库零改动**（已核实：`PUT /api/v1/canned-categories/{id}` 已支持 `sort_order`，树接口已返回每级分类的 `parent_id` / `sort_order`，排序查询为 `order by sort_order asc, id asc`）。

1. **搜索作用域化（纯前端计算，O(n) 一次遍历）**

- 重写 `displayedResponses` computed：无关键词时维持返回 `selectedCategory.responses`；有关键词时以“选中分类节点”为遍历根递归其子树匹配 `content`，命中项挂 `__path`（相对选中分类的路径，选中分类自身命中时为空，模板中 `v-if` 为空的路径行不渲染）；未选中分类返回空数组。
- `selectCategory` 去掉 `search.value = ''`，改为保留关键词。
- 右侧标题在搜索态展示“分类名 · 关键词 (N)”，沿用既有 `displayedResponses.length` 计数。
- 数据量小（分类与常用语全量在内存树中），无需防抖或后端查询，无 N+1 风险。

2. **移除分类行数量**

- 删除分类行模板中渲染 `row.responseCount` 的 `span`，并同步从 `categoryRows` 的产出对象中移除该字段（保持数据结构与模板一致，避免无效计算）。

3. **分类上移/下移（复用既有“交换 sort_order”范式）**

- 参考同文件已实现的 `moveResponse`（两次 PUT 交换 `sort_order`）与 `isFirstResponse/isLastResponse` 禁用逻辑，保持一致风格。
- `categoryRows` 补充 `parentId`、`sortOrder` 字段（数据源来自接口返回的节点，无需额外请求）。
- 新增 `siblingsByParent` computed：按 `parentId`（顶层用统一占位键）聚合树中的同层分类，顺序即接口返回的 `sort_order asc, id asc`，用于判定首/末位与查找相邻项。
- 新增 `moveCategory(row, direction)`：定位相邻兄弟后交换二者 `sort_order`（两次 `updateCannedCategory`，携带各自原有 `name` 与真实 `parent_id`）；若二者 `sort_order` 相同（历史数据可能出现），则按新顺序将整组兄弟重排为 `0..n-1` 后逐个提交，保证移动结果可见；用 `categoryMoving` 标志防止连点重复提交；完成后 `await refresh()` 并保持 `selectedCategoryId`。
- 错误处理走既有 `showError`（`handleHTTPError`），成功静默刷新（与 `moveResponse` 一致，不额外弹成功提示）。

### 性能与可靠性

- 全部为内存内树遍历（分类/常用语规模为百级），单次操作最多 2 次（极端情况 n 次）轻量 PUT，无额外全量拉取除刷新树（与既有响应条目移动行为一致）。
- 保持幂等与最小爆炸半径：不触碰导入/导出/删除等路径；仅增删模板片段与新增少量 computed/方法。
- 复用既有模式，避免引入新的状态管理或抽象层，无技术债新增。
